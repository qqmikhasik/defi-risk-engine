# Связи между требованиями

**Версия:** 0.3, 22.10.2026. Относится к `functional.md` версии 0.3.

Связь означает: при изменении одного требования нужно проверить другое. Каждая связь
записана один раз, действует в обе стороны и сопровождается причиной. Ноутбук
`risk-map.ipynb` читает строки вида `- FR-… ↔ FR-…: причина` и строит по ним трассировку
и граф требований.

У требований, исключённых вместе с хеджем (FR-POS-02, FR-POS-03, FR-POS-09, FR-DATA-05,
FR-RISK-09, FR-RISK-10, FR-RISK-12, FR-DEC-02, FR-DEC-03, FR-DEC-06, FR-OUT-05), связи
не ведутся, пока они не вернутся в проект. Их прежние связи записаны в версии 0.2
`functional.md`.

## MODE

- FR-MODE-01 ↔ FR-DATA-06: backtest исполняется только на фиксированных наборах данных.
- FR-MODE-01 ↔ FR-EXEC-02: решения в backtest исполняются имитацией.
- FR-MODE-01 ↔ FR-OUT-03: результат backtest это журнал решений.
- FR-MODE-01 ↔ FR-OUT-04: результат backtest это отчёт.
- FR-MODE-02 ↔ FR-DATA-02: paper-trading обрабатывает каждый новый блок и событие.
- FR-MODE-02 ↔ FR-EXEC-02: решения в paper-trading исполняются имитацией.
- FR-MODE-02 ↔ FR-MODE-05: рынок, капитал и целевой LTV берутся из настроек.
- FR-MODE-02 ↔ FR-MODE-06: paper-trading работает до сигнала остановки.
- FR-MODE-02 ↔ FR-MODE-07: paper-trading должен переживать обрыв связи с узлом.
- FR-MODE-02 ↔ FR-POS-06: paper-trading заканчивается вместе с позицией.
- FR-MODE-03 ↔ FR-DATA-01: состояние реальной позиции читается из контрактов.
- FR-MODE-03 ↔ FR-EXEC-04: решения в live выводятся рекомендациями.
- FR-MODE-03 ↔ FR-POS-01: live читает позицию на Morpho по её модели.
- FR-MODE-03 ↔ FR-POS-12: live читает позицию на Aave v3 по её модели.
- FR-MODE-03 ↔ FR-MODE-04: live принимает решения тем же кодом, что остальные mode.
- FR-MODE-04 ↔ FR-EXEC-01: mode различаются реализацией интерфейса исполнения.
- FR-MODE-04 ↔ FR-DATA-03: проверка одинаковых решений опирается на записанный порядок событий.
- FR-MODE-05 ↔ FR-POS-05: план открытия строится по рынку, капиталу и LTV из настроек.
- FR-MODE-05 ↔ FR-RISK-15: размер depeg X задаётся в настройках без умолчания.
- FR-MODE-06 ↔ FR-OUT-03: при остановке журнал дописывается до последнего события.
- FR-MODE-07 ↔ FR-DATA-07: отставание данных после обрыва это один из видов сбоя.
- FR-MODE-07 ↔ FR-DATA-08: при обрыве программа переходит на другой узел.
- FR-MODE-07 ↔ FR-MODE-08: обрыв связи при живом процессе и потеря процесса разделены.
- FR-MODE-08 ↔ FR-EXEC-08: после перезапуска состояние сверяется с сетью так же, как после исполнения.
- FR-MODE-09 ↔ FR-MODE-08: автозапуск после падения требует восстановления состояния.
- FR-MODE-09 ↔ FR-OUT-07: сервис на сервере сопровождается по метрикам.

## POS

- FR-POS-01 ↔ FR-RISK-05: LTV и health factor считаются по модели позиции Morpho.
- FR-POS-01 ↔ FR-RISK-11: стоимость выхода считается по долгу и залогу позиции.
- FR-POS-01 ↔ FR-RISK-01: LTV позиции считается по цене оракула рынка.
- FR-POS-04 ↔ FR-POS-01: позиция на Morpho описана моделью FR-POS-01.
- FR-POS-04 ↔ FR-POS-12: позиция на Aave v3 описана моделью FR-POS-12.
- FR-POS-04 ↔ FR-MODE-05: рынок позиции задаётся в настройках.
- FR-POS-05 ↔ FR-EXEC-02: открытие исполняется имитацией с затратами.
- FR-POS-06 ↔ FR-POS-10: доля ликвидированного в имитации уточняется в FR-POS-10.
- FR-POS-06 ↔ FR-POS-11: выход в погашение это один из способов конца позиции.
- FR-POS-06 ↔ FR-POS-12: ликвидация на Aave v3 идёт по правилам FR-POS-12.
- FR-POS-06 ↔ FR-RISK-05: ликвидация наступает при достижении порога из FR-RISK-05.
- FR-POS-06 ↔ FR-DEC-01: досрочное закрытие это одно из решений по позиции.
- FR-POS-08 ↔ FR-MODE-05: в учебном проекте рынок выбирает пользователь в настройках.
- FR-POS-11 ↔ FR-DEC-01: в дату погашения решения по позиции заменяются выкупом.
- FR-POS-11 ↔ FR-EXEC-03: базовый актив меняется на USDC по котировке пула.
- FR-POS-12 ↔ FR-RISK-02: цена залога на Aave v3 берётся у адаптера с линейным дисконтом.
- FR-POS-12 ↔ FR-RISK-05: health factor позиции на Aave v3 считается по её модели.
- FR-POS-12 ↔ FR-RISK-18: ставку дисконта адаптера Aave меняет администратор.
- FR-POS-12 ↔ FR-DATA-01: состояние резерва и позиции Aave v3 читается из контрактов.

## DATA

- FR-DATA-01 ↔ FR-RISK-01: цепочка оракула читается из контрактов рынка.
- FR-DATA-01 ↔ FR-RISK-04: формула оракула сверяется с контрактом.
- FR-DATA-01 ↔ FR-DATA-09: в других сетях нужны те же сверки с контрактами.
- FR-DATA-02 ↔ FR-DATA-03: каждое событие обрабатывается в заданном порядке.
- FR-DATA-03 ↔ FR-OUT-03: порядок событий записывается в журнал.
- FR-DATA-04 ↔ FR-RISK-02: история цены оракула восстанавливается по его формуле.
- FR-DATA-04 ↔ FR-RISK-04: восстановленная цена сверяется с `price()` контракта.
- FR-DATA-04 ↔ FR-RISK-18: история изменений параметров оракула берётся из событий.
- FR-DATA-06 ↔ FR-OUT-03: повторяемость журнала держится на фиксированном наборе.
- FR-DATA-07 ↔ FR-RISK-04: расхождение формулы с контрактом останавливает решения так же, как сбой данных.
- FR-DATA-07 ↔ FR-DEC-07: при ненадёжных данных в продукте разрешено только защитное решение.

## RISK

- FR-RISK-01 ↔ FR-RISK-02: формулы нужны для каждого вида оракула из цепочки.
- FR-RISK-01 ↔ FR-RISK-03: незнакомый компонент цепочки даёт отказ.
- FR-RISK-02 ↔ FR-RISK-04: каждая формула сверяется с контрактом.
- FR-RISK-02 ↔ FR-RISK-06: прогноз цены идёт по формуле оракула.
- FR-RISK-02 ↔ FR-RISK-13: гибридный оракул собран из TWAP и линейного дисконта.
- FR-RISK-02 ↔ FR-RISK-18: ставка дисконта адаптера Aave меняется администратором.
- FR-RISK-03 ↔ FR-RISK-13: пока FR-RISK-13 не реализовано, гибридный оракул даёт отказ.
- FR-RISK-06 ↔ FR-RISK-07: на TWAP прогноз даёт модель скачков implied rate.
- FR-RISK-06 ↔ FR-RISK-15: на линейном дисконте Morpho риск создают долг и depeg.
- FR-RISK-06 ↔ FR-RISK-16: переключение мета-оракула меняет прогноз цены.
- FR-RISK-06 ↔ FR-RISK-18: изменение ставки дисконта меняет прогноз цены.
- FR-RISK-07 ↔ FR-RISK-13: TWAP-составляющая гибридного оракула моделируется так же.
- FR-RISK-07 ↔ FR-RISK-14: качество модели FR-RISK-07 отслеживается в продукте.
- FR-RISK-07 ↔ FR-RISK-17: модель частоты сделок уточняется в продукте.
- FR-RISK-07 ↔ FR-DEC-01: L_U на TWAP задаёт решение сократить плечо.
- FR-RISK-08 ↔ FR-DEC-01: L_L задаёт решение нарастить плечо.
- FR-RISK-11 ↔ FR-EXEC-03: стоимость выхода считается по котировкам пулов.
- FR-RISK-11 ↔ FR-DEC-01: решение закрыть позицию сравнивает доход со стоимостью выхода.
- FR-RISK-15 ↔ FR-RISK-16: таймер мета-оракула сравнивает LTV по резервной цене с L_U.
- FR-RISK-15 ↔ FR-DEC-01: L_U на линейном дисконте Morpho задаёт решение сократить плечо.
- FR-RISK-16 ↔ FR-DEC-04: защита до переключения мета-оракула имеет высший приоритет.
- FR-RISK-18 ↔ FR-DEC-01: L_U на резерве Aave задаёт решение сократить плечо.

## DEC

- FR-DEC-01 ↔ FR-DEC-04: при нескольких поводах решение выбирается по приоритету.
- FR-DEC-01 ↔ FR-EXEC-04: каждое решение в live превращается в рекомендацию.
- FR-DEC-04 ↔ FR-DEC-07: защитное решение при ненадёжных данных встаёт в общий порядок.
- FR-DEC-05 ↔ FR-OUT-02: причина и числа решения выводятся в консоль.
- FR-DEC-05 ↔ FR-OUT-03: причина и числа решения пишутся в журнал.
- FR-DEC-05 ↔ FR-OUT-06: оповещение вне консоли несёт то же объяснение.

## EXEC

- FR-EXEC-01 ↔ FR-EXEC-05: реальное исполнение это ещё одна реализация интерфейса.
- FR-EXEC-02 ↔ FR-EXEC-03: проскальзывание имитации считается по котировке пула.
- FR-EXEC-03 ↔ FR-OUT-04: допущение «цена оракула минус скидка» помечается в отчёте.
- FR-EXEC-05 ↔ FR-EXEC-06: реальное исполнение требует хранения ключей.
- FR-EXEC-05 ↔ FR-EXEC-07: реальное исполнение требует ограничителей.
- FR-EXEC-05 ↔ FR-EXEC-08: реальное исполнение требует сверки после исполнения.

## OUT

- FR-OUT-01 ↔ FR-OUT-02: легенда объясняет величины, которые выводятся в консоль.
- FR-OUT-02 ↔ FR-OUT-03: в консоль идёт часть журнала без решений «держать».
- FR-OUT-03 ↔ FR-OUT-04: отчёт считается по журналу.
