# Указания для ИИ-агента и разработчика

Claude Code читает этот файл через `CLAUDE.md`.

## Назначение

defi-risk-engine: консольная программа на C++ для Linux, проект курса «Технологии в
финансах» (мехмат МГУ, осень 2026). Программа следит за кредитной позицией с плечом в
сети Ethereum (PT-токены Pendle в залоге Morpho или Aave v3, заём в USDC), считает,
насколько позиция близка к ликвидации, и на каждом событии сети решает: держать,
уменьшить заём, увеличить заём или закрыть позицию. Транзакций не подписывает и не
отправляет. Сейчас реализован расчёт LTV и health factor позиции Morpho (FR-POS-01),
остальное описано требованиями.

## Структура

| Путь | Что лежит |
|---|---|
| `src/` | библиотека `defi_risk_core` и программа `main.cpp` |
| `tests/` | модульные тесты на GoogleTest |
| `bench/` | бенчмарки на Google Benchmark |
| `docs/requirements/` | функциональные требования, реестр рисков, трассировка |
| `docs/adr/` | архитектурные решения |
| `.github/workflows/ci.yml` | CI: сборка, тесты, бенчмарк, публикация документации |
| `Doxyfile` | настройки Doxygen |

Внутренняя структура `src/` не задаётся заранее: она следует из архитектуры.

## Команды

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release   # конфигурация, скачивает зависимости
cmake --build build --parallel                    # сборка
ctest --test-dir build --output-on-failure        # тесты
./build/bench/morpho_position_bench               # бенчмарк
doxygen Doxyfile                                  # документация в build/docs/html
```

Эталонная среда задана в `ci.yml`: раннер `ubuntu-24.04`, его g++ и CMake, Doxygen из
пакетов Ubuntu. Локально подходит любой Linux или WSL с CMake 3.25+ и g++ 13+.

## Порядок работы

Требования и архитектурные решения первичны, код вторичен:
`docs/requirements/` → `docs/adr/` → тест → реализация.

- У каждого фрагмента кода есть требование-родитель, его id (например, FR-POS-01)
  указан в комментарии к файлу. Нет требования, нет кода.
- Требований намеренно больше, чем реализованного: подмножество для реализации
  выбирается осознанно, и выбор документируется.
- Требования к производительности формулируются числом и процентилем: «99% пересчётов
  риска быстрее 1 с».
- Архитектурное решение фиксируется ADR до реализации. Раздел «Отклонённые
  альтернативы» обязателен.

## Правила оформления кода

- C++20 без расширений компилятора; код собирается без предупреждений при
  `-Wall -Wextra -Wpedantic`.
- Типы `PascalCase`, функции и переменные `snake_case`, константы `kPascalCase`; весь
  код в пространстве имён `defi_risk`.
- Идентификаторы по-английски, комментарии и документы по-русски.
- У каждого публичного объявления комментарий Doxygen (`///`).
- Недопустимые входные данные: исключение `std::invalid_argument` с понятным сообщением.
- Сообщения коммитов в формате Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`,
  `build:`, `ci:`, `chore:`).

## Ограничения для агента

- Перед завершением задачи собери проект и запусти тесты. Задача не сделана, пока
  сборка идёт с предупреждениями или тесты не проходят.
- Не меняй CI/CD (`.github/workflows/`) и `Doxyfile` без запроса.
- Не добавляй и не обновляй зависимости без запроса. Библиотека подключается по точной
  версии с контрольной суммой, action закрепляется по хешу коммита.
- Не меняй файлы в `docs/requirements/` без запроса.
- Не делай коммит и push без запроса.
- Не клади в репозиторий ключи, пароли и личные данные: репозиторий публичный.
- Не добавляй в программу подпись и отправку транзакций: она только читает сеть
  (требования, раздел 1.2).
