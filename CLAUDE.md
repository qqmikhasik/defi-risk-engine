# Заметки для агента и разработчика

Проект курса «Технологии в финансах» (мехмат МГУ, осень 2026/2027).

## Порядок работы

Требования и архитектурный выбор — первичны, код вторичен:

```
docs/requirements/  →  docs/adr/  →  тест  →  реализация
```

У каждого фрагмента кода есть требование-родитель. Нет требования — код не пишем.
Требований в проекте намеренно больше, чем реализованного: подмножество для реализации
выбирается осознанно, и этот выбор документируется.

## Структура

| Путь | Назначение |
|---|---|
| `docs/requirements/` | функциональные и технические требования. Требования к производительности формулируются числом и процентилем: «99% пересчётов риска быстрее 1 с» |
| `docs/adr/` | архитектурные решения. Раздел «Отклонённые альтернативы» обязателен: решение без отвергнутых вариантов — не решение, а умолчание |
| `src/`, `tests/` | реализация и тесты |

Внутренняя структура `src/` не задана заранее — она следует из архитектуры,
а не предшествует ей.

## Среда

- Эталонная среда описывается `Dockerfile`; локально и в CI собирается один и тот же образ.
- GitHub Actions собирает проект и прогоняет тесты на каждый push.
- Целевая платформа — Linux. Интерфейс — стандартные потоки ввода-вывода, без GUI.

Файлы среды появляются вместе с первым кодом: пустая форма бесполезна.

## Соглашения

- Сообщения коммитов — Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).
- Документы и комментарии — по-русски, идентификаторы в коде — по-английски.
- Каждое архитектурное решение фиксируется ADR до реализации, а не после.
